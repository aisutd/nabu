---------------------------------------------------------------- PRONOUNCIATION — CODE AND RUN NOTES ---------------------------------------------------------------
--------------------------------------------------------------------------------------------------------------------------------------------------------------------

1. FILES AND WORKFLOW

__init__.py marks pronounciation as a Python package.
config.py defines lip landmark IDs, model paths, and default mouth padding.
metrics.py calculates lip geometry and extracts mouth bounding boxes/points.
detector.py detects a face, finds its landmarks, and returns mouth data.
test_webcam.py captures camera frames and displays the measurements.
test_dataset_video.py saves video mouth crops and returns a per-frame metric log.

The first stage locates the face with BlazeFace and selects a padded face region.
The second stage estimates detailed landmarks in that region to measure the lips.

Processing flow:
  BGR frame -> RGB -> face detector -> padded face region -> face landmarker
  -> lip measurements -> full-frame mouth box/points -> display or save.
Both inference tasks use synchronous IMAGE mode, so results belong to the frame
being processed. Call tracker.process_frame(frame) with an OpenCV BGR image.
Its return is (crop, metrics, pts); the empty-result signal is (None,None,None).
close() releases both inference tasks.

2. CONFIGURATION AND NUMBERS

DEFAULT_MODEL_PATH: pronounciation/models/face_landmarker.task
DEFAULT_DETECTOR_PATH: pronounciation/models/blaze_face_full_range.tflite
These paths resolve from the repository-root working directory. The separate
FaceDetector loads the configured detector asset; FaceLandmarker loads its task
bundle and predicts 478 face landmarks on the face region.

The lip IDs are fixed vertex indices in MediaPipe's face-mesh topology:
  Outer upper: 61,185,40,39,37,0,267,269,270,409,291
  Outer lower: 291,375,321,405,314,17,84,181,91,146,61
  Inner upper: 78,191,80,81,82,13,312,311,310,415,308
  Inner lower: 308,324,318,402,317,14,87,178,88,95,78
Each contour closes at its starting vertex. The stored arrays contain 20 unique
outer and 20 unique inner vertices, combined into ALL_LIP_INDICES as int32.
13/14 identify the upper/lower inner centers; 61/291 identify the mouth corners.
0/17 are the upper/lower outer centers; 78/308 are the inner corner endpoints.
Intermediate IDs follow the corresponding contour. int32 means 32-bit integers;
float32 is the 32-bit floating-point type used for crop-coordinate arrays.

MouthTracker defaults:
  face_margin=0.25: expand each face-box side by 25% of that box's width/height.
    A 200x160 box gets 50 horizontal and 40 vertical pixels on each side.
  detection_interval=1: run face detection every frame.
    MouthTracker(detection_interval=5) reuses the face region between detections,
    refreshing on frame indices 0,5,10,...; landmark inference still runs each time.
  min_detection_confidence=0.5: face-detector acceptance threshold.
  num_faces=1: request one face from the landmarker.
  DEFAULT_PADDING=25: add 25 full-image pixels on each side of the mouth box.

3. detector.py DETAILS AND DESIGN

__init__ checks both model paths, requires detection_interval >= 1, creates the
two tasks, and initializes cached bounds, frame count, and frame dimensions.

_detect_face_bounds wraps RGB pixels in mp.Image, selects the first detected
face, expands its box by face_margin, and clips the starting/ending boundaries.
It returns (x1,y1,x2,y2) when the rectangle has positive width and height.

process_frame converts BGR to RGB and refreshes detection when the interval is
reached, the cached region is empty, or the image dimensions change. It makes
the face-region RGB array contiguous with np.ascontiguousarray for MediaPipe.
The landmarker runs on that region. An empty landmark result clears the cached
bounds so the next frame attempts face detection again.

Mouth coordinates and measurements are calculated directly in the face region.
The region origin (fx1,fy1) is added to drawing points and box endpoints. Padding
is applied in full-frame coordinates, and the mouth image is sliced from the
original BGR frame. metrics["bbox"] stores [x1,y1,x2,y2].

This organization keeps face-box logic in one helper and avoids creating a
replacement object for every face landmark. DEFAULT_PADDING centralizes the
mouth-margin default. Optional region reuse reduces face-detection calls.

4. metrics.py MATH

For the face-region width W and height H, normalized coordinates become pixels:
  x_pixel = landmark.x * W
  y_pixel = landmark.y * H

  aperture_px = abs(y14 - y13)
  stretch_px = abs(x291 - x61)
  aspect_ratio = aperture_px / (stretch_px + 1e-6)

Aperture is vertical inner-lip opening; stretch is horizontal mouth width.
Both are in pixels. The ratio is dimensionless. abs makes distances positive;
1e-6 is 0.000001, an epsilon that prevents a zero denominator.
Example: opening=36 px and width=256 px -> ratio approximately 0.140625.
Under uniform scaling, opening and width scale together, preserving their ratio
approximately. Translating coordinates leaves these differences unchanged.

extract_mouth_crop gathers the 40 lip coordinates, finds min/max x/y, converts
bounds to integers, and applies its padding. In detector.py it is called with
padding=0; the detector then adds DEFAULT_PADDING to the translated mouth box.
NumPy slicing uses frame[y1:y2,x1:x2], with exclusive end boundaries. pts has
shape (40,2), with integer [x,y] rows. The metrics dictionary contains Python
floats plus the full-frame bbox added by the tracker.

5. test_webcam.py DISPLAY

VideoCapture(0) selects camera zero; 1280x720 requests a 16:9 capture image.
Each successful read goes directly to process_frame. A nonempty crop is shown
in Mouth Crop (ROI); the camera image is shown in Webcam Feed.

Display numbers:
  .1f: one decimal for pixel measurements; .2f: two decimals for the ratio.
  (30,50): text-baseline origin in pixels; 0.8: font scale; 2: stroke thickness.
  (0,255,0): green text; (0,0,255): red points; (255,0,0): blue box, all BGR.
  Circle radius=1 pixel; thickness=-1 fills each circle.
  waitKey(1): GUI/key processing with a nominal 1-ms wait.
  0xFF=255: low-byte key mask; ord('q')=113: lowercase exit key.
On exit, the runner releases the camera, closes both tasks, and closes windows.

7. test_dataset_video.py

process_dataset_clip(video_path, output_dir="pronounciation/crops") checks the
input path, creates the output folder, and opens the video with MouthTracker.
FPS comes from the video, with 30.0 as the fallback. Frames are numbered from 0.
  timestamp_ms = int(frame_idx / fps * 1000)
This converts frame position to milliseconds for the log. process_frame(frame)
uses the default mouth padding and synchronous inference.

Each valid mouth crop is saved as frame_0000.jpg, frame_0001.jpg, etc.; :04d
formats the frame index with at least four digits. Its log entry records
frame_idx, timestamp_ms, aperture_px, stretch_px, and aspect_ratio.
The function returns this list and prints mean/maximum aperture and aspect ratio.
Mean is the sum divided by the number of logged frames; maximum is the largest
logged value. The runner releases the camera and closes both inference tasks.
