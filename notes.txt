Pipeline overview
-----------------
Browser camera/upload -> React practice page -> API client -> FastAPI upload
-> FFmpeg MP4 conversion -> saved UUID video.
  Transcription: video -> 16 kHz mono WAV -> Whisper -> heard text / match.
  Comparison: user + example video -> face/lip detection -> idle trimming
  -> normalized mouth features -> dynamic time warping -> error / feedback
  -> PNG plot + JSON -> React results.

Desktop collection: webcam + microphone -> landmarks + timestamps -> idle
trimming -> labeled dataset.csv + matching WAV/MP4 -> review tools.
Training preparation: existing raw NPZ or Hugging Face video -> normalized
landmarks -> optional 29-frame single-word sequences -> CSV export.
Handwriting is a separate API/test frontend; it is not wired into the current
React pronunciation page.

pronounciation/ — collection, analysis, and API
---------------------------------------------
__init__.py: Marks the directory as a Python package.
config.py: Shared lip landmark indices, crop padding, and local model paths.
detector.py: MouthTracker detects a face, estimates face landmarks, extracts
  40 lip XYZ points in full-frame coordinates, and produces mouth crops/metrics.
metrics.py: Calculates mouth aperture/stretch/aspect metrics and crop bounds.
trim.py: Estimates mouth activity and trims idle landmark frames.
video_input.py: Reads videos into timestamped landmark sequences; FFmpeg
  converts input audio to 16 kHz mono 16-bit WAV for Whisper.
transcribe.py: Lazily loads Whisper small.en on CPU; returns word timing and
  confidence, then checks recognized text against the expected label.
compare.py: Normalizes mouth geometry, extracts features, aligns sequences
  with dynamic time warping, generates stage feedback and plots; also a CLI.
api.py: FastAPI upload/transcription/comparison endpoints, UUID storage,
  FFmpeg conversion, CORS configuration, processing lock, and /media serving.
test_webcam.py: Interactive desktop collection entry point; coordinates
  tracking, audio/video recording, labeling, trimming, saving, and audio checks.
recorder.py: Appends labeled landmark frames and timestamps to dataset.csv;
  allocates integer recording IDs.
audio_record.py: Captures microphone audio and writes PCM WAV recordings.
video_record.py: Captures video frames and uses FFmpeg to attach saved audio.
check_confidence.py: Looks up saved integer recording IDs and checks their
  audio transcription against the dataset label.
view_trim.py: Loads CSV recordings and plots activity/trim boundaries.
test_dataset_video.py: Extracts mouth crops from a prerecorded test clip.
preprocess_recordings.py: Loads existing raw NPZ recordings, centers/scales
  mouth points, and resamples eligible single-word sequences to 29 frames.
export_csv.py: Exports raw NPZ recordings to CSV; inspect path constants first.
export_normalized_csv.py: Exports normalized 29-frame NPZ sequences to CSV;
  inspect path constants first.
huggingFaceTest.py: Reads Hugging Face dataset metadata for inspection.
test_hug_landmarks.py: Downloads a sample clip/model as configured and previews
  landmark detection; its MODEL default is a Windows-specific path.
preprocess_hug_landmarks.py: Downloads dataset clips, detects/normalizes lip
  landmarks, and writes processed NPZ files; supports limits and preview.
models/face_landmarker.task: MediaPipe face landmark model asset.
models/blaze_face_full_range.tflite: MediaPipe face detection model asset.
test_data/dataset.csv: Desktop collection's labeled frame data.
test_data/audio/: Saved microphone WAVs and temporary prepared audio.
test_data/video/: Saved desktop/reference videos.
test_data/api/: Uploaded UUID MP4s, extracted WAVs, and API plots/ subfolder.
test_data/recordings/: Raw NPZ inputs used by the older preprocessing workflow.
test_data/plots/ and test_data/comparisons/: CLI comparison images.
test_videos/: Prerecorded clips for crop diagnostics.
crops/: Mouth images produced by crop diagnostics.
file and roles.txt: More detailed pronunciation schemas and implementation notes.

handwriting/ocr/ — separate handwriting pipeline
-----------------------------------------------
api.py: FastAPI image-upload endpoints for OCR text, scored tuples, and
  handwriting error locations; serves its frontend at /tester.
ocrfuncs.py: Caches PaddleOCR models by language, extracts text/results, and
  restores signal handlers used by the API server.
errorfinder.py: Converts SVG/image ink and expected rendered text into points,
  normalizes geometry, uses nearest-neighbor distances to find errors, and
  filters/combines error locations for feedback.
fonts/: Bundled fonts for rendering expected text across supported scripts.
frontend/index.html: Browser tester for the handwriting API.
testocr.py: Manual OCR diagnostic script.
testerrorfinder.py: Manual error-finder diagnostic script.
testch.svg: SVG sample for handwriting diagnostics.
planning.md: Handwriting design ideas and planned work.

                                                                  3. Setup + steps to run
==================================================================================================================================================

Run pronunciation commands from the nabu repository root. The package name
is spelled pronounciation. Handwriting commands below use --app-dir because
that API currently uses sibling imports.

External dependencies — not installed by requirements.txt
--------------------------------------------------------
Python requirements install Python packages only. Run the following setup
commands separately; do not put shell commands in requirements.txt.

macOS prerequisites (Homebrew must already be installed):
- Python 3 with venv/pip, Git, Node.js/npm, and FFmpeg on PATH.
- Use Node.js 22.12+ in the 22.x line, or a newer supported LTS release.
  The installed Vite requires ^20.19.0 or >=22.12.0; Capacitor CLI requires
  >=22.0.0, so Node 20 does not cover the entire project's tooling.
- Install any missing tools, rather than reinstalling tools you already have:
    brew install python git node ffmpeg
- Verify your terminal can find them:
    python3 --version
    git --version
    node --version
    npm --version
    ffmpeg -version
  FFmpeg must include libx264 encoding for API uploads:
    ffmpeg -encoders
  Look for libx264 in the encoder list.

Python environment (from the repository root):
  python3 -m venv .venv
  source .venv/bin/activate
  python -m pip install --upgrade pip
  python -m pip install -r requirements.txt
  python -m pip check
Select .venv/bin/python as the VS Code Python interpreter. Python package
compatibility depends on Python version and platform; the full pinned file
has not yet been validated with a clean install.

Frontend dependencies, including Tailwind and its Vite plugin:
  cd UI
  npm ci
  cd ..
These come from UI/package.json and package-lock.json, not requirements.txt.
Tailwind is already configured; no extra global Tailwind installation is needed.

Model assets and first-use downloads:
- Keep these files at the paths expected by config.py:
    pronounciation/models/face_landmarker.task
    pronounciation/models/blaze_face_full_range.tflite
  They are local assets, not pip packages; restore them from your project/model
  source if missing. Run the pronunciation backend from the repository root.
- Whisper downloads small.en on first use if it is not cached.
- PaddleOCR downloads requested language models when needed.
- Optional Hugging Face scripts download metadata/videos and need network access.
- Keep handwriting/ocr/fonts/ available for expected-text rendering.

Camera, microphone, and desktop audio:
- Allow camera/microphone access in macOS Privacy & Security for the browser
  and terminal/IDE used for recording.
- Browser recording needs localhost or HTTPS and MediaRecorder support.
- Desktop OpenCV previews need a graphical desktop; headless environments
  cannot display these windows.
- sounddevice uses PortAudio. Its normal pip installation bundles PortAudio
  on macOS/Windows, so a separate install is usually unnecessary.
  If macOS reports a missing PortAudio library, install it with:
    brew install portaudio
  Linux may need its distribution's PortAudio runtime package separately.
  Check microphone devices inside the activated environment:
    python -m sounddevice
  Reference: https://python-sounddevice.readthedocs.io/en/latest/installation.html

Optional native builds (not required for browser development):
- Android: Android Studio, Android SDK, and a compatible JDK for the native
  Gradle project. After npm run build in UI, use npx cap sync android and
  npx cap open android.
- iOS: macOS with Xcode and its command-line tools. After npm run build in UI,
  use npx cap sync ios and npx cap open ios.
- Docker Desktop is needed only for Docker commands. The current compose
  file starts a placeholder container; it does not run this application.

Web app — primary run path
--------------------------
First create/activate the Python environment and install dependencies using
step 1 below. Install FFmpeg and check that both model files exist.

Terminal 1, from the repository root:
  source .venv/bin/activate
  python -m uvicorn pronounciation.api:app --reload --port 8000

Terminal 2, from the repository root (Node.js and npm required):
  cd UI
  npm ci
  npm run dev

Open the URL printed by Vite, usually http://localhost:5173.
1) Enter the word/phrase.
2) Upload a reference video for mouth-movement comparison.
3) Enable the camera, allow camera/microphone permission, start/stop a capture;
   or upload your own recording. Keep your mouth visible and include audio.
4) Use the transcription or comparison action and inspect the results.
   Transcription needs user audio; mouth comparison needs both videos.

The Vite proxy connects the browser to the API on port 8000. Browser recording
requires localhost or HTTPS and a browser supporting MediaRecorder.
Whisper may download small.en on first transcription; allow time/network access.
Stop each development server with Ctrl+C.

Frontend checks / production build:
  cd UI
  npm run lint
  npm run build
  npm run preview

For deployment, set VITE_API_BASE_URL to the reachable backend before building,
and configure NABU_ALLOWED_ORIGINS on the backend for the frontend origin.
Vite's development proxy is not included in the production build.

Handwriting API + tester — optional, separate server
----------------------------------------------------
From the repository root with the Python environment activated:
  python -m uvicorn api:app --app-dir handwriting/ocr --port 8001

Open http://127.0.0.1:8001/tester/ for the handwritten-image tester,
or http://127.0.0.1:8001/docs for endpoint documentation.
PaddleOCR may download language models on first use. This API has custom
shutdown handling; start without --reload initially.

Desktop collection / CLI / data preparation
-------------------------------------------
1. SET UP THE ENVIRONMENT

Create the virtual environment if it does not already exist:
  python3 -m venv .venv

Activate it and install dependencies:
  source .venv/bin/activate
  python -m pip install -r requirements.txt

Check FFmpeg:
  ffmpeg -version

If FFmpeg is missing on macOS with Homebrew:
  brew install ffmpeg

Confirm both local model files are present:
  pronounciation/models/face_landmarker.task
  pronounciation/models/blaze_face_full_range.tflite

Enable camera and microphone access for your terminal/IDE. Use an environment
with OpenCV window support. Whisper may download its model on first use.

2. RECORD YOUR UTTERANCE

  python -m pronounciation.test_webcam

Focus an OpenCV window and press any key except lowercase q to start recording.
Say the word or phrase with your lips clearly visible. Press the SAME key to stop.
The recording needs at least 30 detected mouth frames before trimming; keep
recording long enough to meet the displayed valid-frame count.

In the terminal, enter exactly what you said. Leave the label empty to discard.
Note the recording ID printed after saving. At the next terminal prompt, press
Enter to record again, or type q and Enter to finish. Lowercase q in the OpenCV
window quits and discards an active recording.

For a successfully saved ID N, check:
  pronounciation/test_data/dataset.csv
  pronounciation/test_data/audio/recording_N.wav
  pronounciation/test_data/video/recording_N.mp4

Check the terminal for save/conversion errors and the Whisper result. Review
mismatches manually before using a capture as a reference or training example.

3. REVIEW A SAVED RECORDING

Replace 29 below with the ID printed during your recording:
  python -m pronounciation.check_confidence 29
  python -m pronounciation.view_trim 29

Multiple IDs can be checked together:
  python -m pronounciation.check_confidence 28 29 31
  python -m pronounciation.view_trim 28 29 31

Play the saved video on macOS:
  open pronounciation/test_data/video/recording_29.mp4

4. CHOOSE A REFERENCE VIDEO

Choose a clear video of the SAME word/phrase spoken correctly. You can record
another take with step 2 or use an existing reference. Check the actual content
rather than relying only on the filename or typed label.

The examples below use these local files; replace them with your chosen pair:
  User:      pronounciation/test_data/video/recording_29.mp4
  Reference: pronounciation/test_data/video/june.mp4
  Word:      june

The local june.mp4 and Kent.mp4 references have no audio stream. They can be
used for visual comparison; use an audiovisual recording for transcription.

5. COMPARE MOUTH MOVEMENT

Show the supported options:
  python -m pronounciation.compare --help

Run a comparison with the default word-named output:
  python -m pronounciation.compare \
    --user pronounciation/test_data/video/recording_29.mp4 \
    --example pronounciation/test_data/video/june.mp4 \
    --word june

Open the output on macOS:
  open pronounciation/test_data/plots/june.png

For a custom output filename:
  python -m pronounciation.compare \
    --user pronounciation/test_data/video/recording_29.mp4 \
    --example pronounciation/test_data/video/june.mp4 \
    --out pronounciation/test_data/comparisons/recording_29.png

Supply --word when using the default output, or supply --out for a custom path.
Reusing an output path overwrites the previous plot. Read the terminal feedback
and inspect the plot; interpretation and limitations are in file and roles.txt.

6. COMPARE AND CHECK THE USER'S AUDIO

Use the matching saved microphone WAV:
  python -m pronounciation.compare \
    --user pronounciation/test_data/video/recording_29.mp4 \
    --example pronounciation/test_data/video/june.mp4 \
    --user-wav pronounciation/test_data/audio/recording_29.wav \
    --word june \
    --out pronounciation/test_data/comparisons/recording_29_audio.png

Alternatively, use audio embedded in the USER video:
  python -m pronounciation.compare \
    --user pronounciation/test_data/video/recording_29.mp4 \
    --example pronounciation/test_data/video/june.mp4 \
    --user-wav pronounciation/test_data/video/recording_29.mp4 \
    --word june \
    --out pronounciation/test_data/comparisons/recording_29_embedded_audio.png

Both --user-wav and --word are needed to enable the audio check. Check the
terminal's recognized text as well as the plot. These commands overwrite the
scratch file pronounciation/test_data/audio/_prepared_user.wav on each audio run.

7. OPTIONAL SELF-COMPARISON CHECK

  python -m pronounciation.compare \
    --user pronounciation/test_data/video/recording_29.mp4 \
    --example pronounciation/test_data/video/recording_29.mp4 \
    --out pronounciation/test_data/comparisons/self_check.png

  open pronounciation/test_data/comparisons/self_check.png

Expect very small shape differences when repeated detections are consistent.

8. RUN THE SAME TESTS THROUGH THE API

Start the server in an activated terminal:
  python -m uvicorn pronounciation.api:app

Open the interactive API documentation:
  http://127.0.0.1:8000/docs

In the documentation forms:
  1) POST /recordings: upload the user MP4 using the video file field. Execute
     and copy the returned UUID id.
  2) POST /recordings: upload the reference MP4 and copy its UUID id.
  3) Optional POST /recordings/{recording_id}/transcription: enter the USER UUID
     and expected label, then Execute. The user's MP4 must contain audio.
  4) POST /comparisons: enter user_id, example_id, and label in the query fields,
     then Execute.
  5) Open the returned png_url using the server address, for example:
     http://127.0.0.1:8000/media/plots/june.png

Use the UUIDs returned by upload, not the integer IDs from webcam recording.
Repeated comparisons with the same sanitized label overwrite the same API plot.
Stop the server with Ctrl+C when finished.

9. OPTIONAL PRERECORDED CORPUS CROP TEST

Corpus references for choosing a test clip:
  Raw data: https://doi.org/10.6084/m9.figshare.24615378
  Processed slices: https://doi.org/10.6084/m9.figshare.24612312
  Corpus index: https://doi.org/10.6084/m9.figshare.24615705

Choose an archive after checking its size, extract it, and use Corpus_index.xlsx
when available to identify the utterance. Select an RGB video clip.

Place it at the test entry point's expected location:
  mkdir -p pronounciation/test_videos
  cp /path/to/extracted/video.mp4 pronounciation/test_videos/sample_clip.mp4
  python -m pronounciation.test_dataset_video

Inspect the images in pronounciation/crops/ for both mouth corners and the full
lip opening. Use a separate output folder when testing another clip in Python:
  from pronounciation.test_dataset_video import process_dataset_clip
  log = process_dataset_clip('path/to/clip.mp4', 'pronounciation/crops/my_clip')

To compare a corpus clip with your recording, use its path as --example in
steps 5/6, after confirming both clips contain the same utterance.

10. OPTIONAL TRAINING-DATA PREPARATION COMMANDS

Read the input schemas and path requirements in file and roles.txt first.
These commands prepare data; there is no model training command in this folder.
The current live dataset.csv is not accepted directly by the NPZ preprocessor.

For an existing raw NPZ with the required keys (replace the placeholder path):
  python -m pronounciation.preprocess_recordings \
    --input path/to/raw_recording.npz \
    --output-dir pronounciation/test_data/processed_webcam

Before running either exporter, edit its input/output path constants for your
machine and chosen data directory. Exports overwrite their destination CSV:
  python -m pronounciation.export_csv
  python -m pronounciation.export_normalized_csv

Inspect Hugging Face metadata:
  python -m pronounciation.huggingFaceTest

For the Hugging Face commands below, first correct MODEL in each script for
your machine. Their defaults use Windows-style paths, not the local models/
path automatically. The preprocessor requires its model file already exists.

Run the landmark diagnostic:
  python -m pronounciation.test_hug_landmarks

Prepare one clip with a preview:
  python -m pronounciation.preprocess_hug_landmarks \
    --limit 1 \
    --preview \
    --output-dir pronounciation/test_data/processed_hf_landmarks

Use --limit 0 only when you intend to process all metadata rows. To export
these outputs, explicitly point the normalized exporter's input constant to
the Hugging Face output directory and choose a separate destination CSV.
